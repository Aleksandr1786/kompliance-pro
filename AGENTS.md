# КомплаенсПро — десктоп (Electron). Инструкции для агентов

Этот файл — канонические правила работы с репозиторием. Он читается в начале каждой задачи и должен оставаться актуальным.

## Проект и связь с веб-версией

Это исходное Electron-приложение: Electron + Vanilla JS + lowdb, данные хранятся локально на диске пользователя. Публичный репозиторий используется для обновлений через `electron-updater`, поэтому публикация изменений может затронуть действующих подписчиков.

Веб-версия находится в приватном репозитории `Aleksandr1786/kompliance-web`. Веб — эталон архитектуры и UI; десктоп приводится к нему при расхождениях без урезания функциональности. Актуальную структуру проекта определяй инвентаризацией, а не по статическому перечню в этом файле.

## Данные и секреты

Реальная база приложения лежит в `%APPDATA%\kompliance-pro\kompliance.json` или аналоге для ОС и не должна попадать в репозиторий. Если обнаружены реальные данные клиентов, не изучай их сверх необходимого для диагностики, не копируй в отчёты и остановись перед любыми действиями, способными их опубликовать.

Не изменяй и не публикуй `.env`, ключи, токены, пароли, лицензионные данные и файлы с именами `*key*`, `*secret*`. Не выводи их содержимое в отчёты и логи.

## Git и публикация

- Не работай напрямую в `master`. Для каждой задачи используй отдельную ветку `agent/<краткое-название>`.
- Разрешено готовить небольшие логические коммиты и draft PR для проверки человеком.
- Не выполняй merge, релиз, публикацию или деплой без явного подтверждения человека.
- Не создавай GitHub Release и не публикуй артефакты Electron самостоятельно.
- Перед релизом версия в `package.json` должна быть повышена. Если готовится релизное изменение, явно напомни об этом в PR или отчёте.
- Перед серьёзной правкой проверь чистоту рабочей копии и отдели посторонние изменения.

## Доменные правила

- Генераторы документов и `doc-meta.js` меняются вместе только при реальном изменении НПА. Для опечатки или редакционной формулировки версию документа не повышай.
- Региональная отчётность поддерживает только Краснодарский край. Не переноси формы и сроки других регионов по аналогии.
- При работе с нормализацией города проверь исправление для городов на «Г»: `.replace(/^г(?:\.\s*|\s+)/i,'').replace(/^город\s+/i,'')`.
- Склонение ФИО руководителя и ответственных лиц — отдельная задача; не исправляй её походя.
- Визуал готовности сверяй с веб-версией: сегментные кольца и честное среднее по подключённым модулям.

## Работа между репозиториями

- Сначала выполни сравнение только чтением: что отсутствует, различается или уже исправлено в каждой версии.
- Не переноси код автоматически до согласования результатов сравнения.
- Если задача затрагивает обе версии, используй отдельные ветки и отдельные PR в каждом репозитории, добавив взаимные ссылки.
- Веб задаёт архитектурное и визуальное направление, но различия платформы Electron и локального хранения учитываются явно.

## Проверка и отчёт

Проводи релевантные тесты и проверки перед завершением задачи. В PR укажи, что изменено, зачем, какие проверки выполнены и что остаётся подтвердить человеку. Для крупного сравнительного анализа создай отдельный отчёт только если это нужно для дальнейшего решения.
