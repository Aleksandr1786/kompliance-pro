# КомплаенсПро — десктоп (Electron). Инструкции для Claude Code

Этот файл читается в начале каждой сессии. Здесь — то, что должно быть
верным всегда, независимо от конкретной задачи.

## Что это за проект и чем отличается от веб-версии

Исходное Electron-приложение (Electron + Vanilla JS + lowdb, всё
локально на диске пользователя). Публичный репозиторий — через него
работает `electron-updater`, то есть **любой закоммиченный и запушенный
код может уехать живым подписчикам при следующем обновлении.**

Параллельно существует веб-версия (отдельный репозиторий `kompliance-web`,
не на GitHub). **Дизайн-приоритет: веб — эталон архитектуры и UI, этот
репозиторий подгоняется под веб при расхождениях, без урезания
функционала при переносе.**

Точную структуру папок (модули, engine/генераторы, main/preload,
mcp-server) выясняй самостоятельно инвентаризацией в начале работы —
она менялась в ходе рефакторинга монолитного `app.js` на ~17 модулей,
этот файл её не дублирует, чтобы не разойтись с реальностью.

## Данные пользователя — вне репозитория, но будь внимателен

Реальная база данных приложения лежит в
`%APPDATA%\kompliance-pro\kompliance.json` (или аналог для конкретной
машины) — она НЕ часть репозитория и не должна там оказаться. Если в
рабочей копии всё же встретится файл с реальными данными клиентов
(ФИО, ИНН, адреса) — не читай его содержимое дальше, чем нужно для
диагностики, и не копируй фрагменты в отчёты.

## Три жёстких запрета

1. **Никакого деплоя и публикации.** Не пушь в `origin`/GitHub
   самостоятельно ни при каких обстоятельствах — публикацию делает
   человек вручную, после ревью. Твоя работа заканчивается на локальных
   коммитах.
2. **Перед любым пушем — версия в `package.json` поднята.**
   `electron-updater` определяет новое обновление по версии; если её не
   поднять, обновление до подписчиков просто не дойдёт незаметно для
   всех. Это ответственность человека перед пушем, но если ты готовишь
   коммит для публикации — напомни об этом явно в отчёте.
3. **Не трогать файлы с секретами и лицензионные ключи** (что бы это ни
   было в конкретной структуре — файлы вида `*.env`, `*keys*`,
   `*secret*` открывай только для чтения структуры, не для правки, и не
   выводи содержимое в отчёты).

## Правила, накопленные на практике (актуальны и для десктопа)

- **Генераторы документов и `doc-meta.js` меняются вместе.** Правишь
  текст в `gen_*.js` из-за реальной смены НПА — обнови `version`/`npa` в
  `doc-meta.js` в том же изменении. Если правка — опечатка или
  формулировка без смены закона, версию НЕ поднимать: иначе пользователю
  покажется «обновлены требования законодательства», что неправда.
- **Региональная отчётность поддерживает только Краснодарский край.** Не
  копировать формы/сроки других регионов по аналогии.
- **Известный баг с городами на «Г», уже исправлен в веб-версии
  28.07.2026** — в файлах, аналогичных `engine/gen_p1.js` (функция
  нормализации города) и `engine/doc-generation.js`. Выражение вида
  `/^г\.?\s*/i` срезает первую букву у городов на «Г»: «Геленджик» →
  «еленджик», «город Геленджик» → «ород Геленджик». Правильное
  выражение: `.replace(/^г(?:\.\s*|\s+)/i,'').replace(/^город\s+/i,'')`.
  **Если такая же функция есть в этом репозитории — она с высокой
  вероятностью содержит тот же баг, проверь и продублируй исправление.**
- **Известный пробел:** склонение ФИО через AI работает только для полей
  сотрудников, не для руководителя/ответственных лиц — они попадают в
  документы в именительном падеже вместо нужного. Отдельная задача, не
  чинить походя.
- **Единый стиль колец готовности** (сегментные кольца, честное среднее
  по подключённым модулям) уже унифицирован в вебе и частично в
  десктопе — при доработке визуала готовности сверяться с веб-версией,
  не изобретать заново.

## Как работать над задачами

- Если задача — сравнение с веб-репозиторием: **сначала только чтение**,
  без единой правки. Собери инвентаризацию (что есть здесь и нет в вебе,
  что есть в вебе и нет здесь, что реализовано по-разному), не переноси
  код самостоятельно — решения о переносе принимает человек в чате поверх
  твоего отчёта.
- Пиши отчёты в файл, не только в диалог.
- Мелкие коммиты, чистое `git status` перед серьёзной правкой.
