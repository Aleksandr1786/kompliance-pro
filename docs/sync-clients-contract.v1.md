# Контракт синхронизации клиентов и сотрудников — v1

**Версия протокола: 1**  
**Зафиксировано:** 01.08.2026

Этот документ описывает фактически используемый контракт между веб-сервисом КомплаенсПро и настольным приложением. Изменения контракта должны одновременно сопровождаться проверками в обоих репозиториях.

## Точка обмена

- Метод: `POST`
- Путь: `/api/sync-clients`
- Авторизация: `Authorization: Bearer <token>`
- Формат: `application/json`

Контракт охватывает клиентов и сотрудников. Воинский учёт и отправка отчётов синхронизируются отдельными маршрутами.

## Запрос

```json
{
  "clients": [{
    "desktop_local_id": "local-client-id",
    "cloud_id": "uuid-or-null",
    "updated_at": "2026-08-01T12:00:00.000Z",
    "deleted": false,
    "data": {}
  }],
  "employees": [{
    "desktop_local_id": "local-employee-id",
    "cloud_id": "uuid-or-null",
    "client_desktop_local_id": "local-client-id",
    "client_cloud_id": "uuid-or-null",
    "updated_at": "2026-08-01T12:00:00.000Z",
    "deleted": false,
    "data": {}
  }]
}
```

`desktop_local_id` — непрозрачный локальный идентификатор. `cloud_id` — канонический UUID сервера. `updated_at` передаётся в RFC 3339 UTC.

Перед отправкой и перед сохранением `data` очищается по реестру `data-contract.js`. Локальные `id`, `client_id`, `cloud_id`, настройки, токены, ключи и неизвестные поля в JSON не передаются и не сохраняются. Медицинские допуски допускают только утверждённые типы и поля факта допуска; диагнозы и произвольный медицинский текст не входят в контракт.

## Ответ

```json
{
  "status": "ok",
  "contract_version": 1,
  "clients": [],
  "employees": [],
  "pulled_clients": [],
  "pulled_employees": [],
  "deleted_client_ids": [],
  "deleted_employee_ids": []
}
```

Элементы `clients` и `employees` могут содержать `conflict: true`, `server_data` или `deleted_on_server: true`.

## Конфликты

- Входящая запись принимается, если её `updated_at` не старше серверной.
- Более старая запись не перезаписывает серверную: возвращаются `conflict: true` и `server_data`.
- Клиент обязан явно обработать конфликт; молчаливое затирание данных запрещено.

## Удаление

- `deleted: true` создаёт серверную отметку удаления.
- Сервер сообщает удалённые объекты через `deleted_on_server` и списки `deleted_*_ids`.
- Серверные tombstone-записи возвращаются в течение 30 дней.
- Текущее поведение v1: настольное приложение архивирует удалённых клиентов и удаляет локальные записи сотрудников.

## Надёжность и совместимость

- Повторная отправка одного объекта должна быть идемпотентной.
- Неизвестные дополнительные поля ответа игнорируются потребителем.
- Ломающие изменения требуют нового маршрута (например, `/api/v2/sync-clients`) либо явного согласования версии.
- Изменение поведения допускается только после обновления этого документа и контрактных тестов в обоих репозиториях.
